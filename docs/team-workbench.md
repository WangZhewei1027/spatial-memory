# 团队工作台与地图合集

本文说明前端信息架构和数据流。团队权限见 [权限体系](permissions.md)，服务端请求与一致性规则见 [后端契约](team-workbench-backend-contract.md)。

## 内容组织

Organization 在界面上称为团队。团队拥有素材、Scene 和活动，成员共享全部内容；地图合集对应 workspace 行，只组织投放和标签。同一素材、场景可在多个合集投放；一个活动最多关联一个地图合集。活动记录独立于基础素材。

新团队没有默认合集。上传素材、创建/导入/复制场景不需要选择合集；普通内容投放时才指定位置和合集。素材、场景直接保存当前内容；活动的固定地点在活动内容中维护，投放只关联地图。

## 页面入口

| 路由 | 内容 |
| --- | --- |
| `/manage` | 默认进入基础素材，保留团队上下文 |
| `/manage/assets` | 素材缩略图网格、搜索、类型和归档筛选、上传；点击卡片在右侧单列浮岛显示详情 |
| `/manage/assets?assetId=[id]` | 保留列表上下文的素材详情：预览、编辑当前内容、使用记录、重命名、副本、归档/恢复 |
| `/manage/assets/[id]` | 直接链接或新标签页访问的完整素材详情 |
| `/manage/activities` | 独立活动库，创建店铺打卡或弹幕留言活动 |
| `/manage/activities/[id]` | 独立活动编辑器；弹幕和店铺打卡共用设置、地图、右侧检视器/关联/记录三栏与顶栏保存 |
| `/manage/anchors` | 识别目标库；只查询 `file_type=anchor`，复用素材网格、搜索、归档筛选和右侧详情浮岛 |
| `/manage/anchors/[id]` | 独立识别目标详情；管理名称、1–5 张识别图、使用记录、副本和归档/恢复 |
| `/manage/scenes` | 场景库、搜索、归档筛选、新建与 JSON 导入 |
| `/manage/scenes/[id]` | 场景编辑器、团队模型选择、保存与二维码预览；返回场景列表 |
| `/manage/collections` | 合集列表、新建与归档/恢复；团队级小程序二维码 |
| `/manage/collections/[id]` | 全窗口地图编辑器；合集名称、归档状态与合集二维码 |
| `/upload-onsite` | 页面内选择团队/合集，确认位置后上传并投放 |
| `/admin/settings`、`/admin/members` | 按权限提供团队设置和成员管理 |

侧边栏按地图合集、活动、识别目标、场景、基础素材排列，桌面常驻，窄屏通过抽屉展开。合集与活动卡片在新标签页打开各自的编辑器，保留原列表。地图、Scene 和活动编辑器隐藏主页 navbar 与团队侧栏，使用各自完整工作空间；地图选择状态只在当前地图上下文使用。活动库右上角的“创建活动”打开名称与类型表单弹窗；创建成功后关闭弹窗、留在活动库并刷新列表，成功提示中的编辑操作在新标签页打开新活动。

## 数据与权限

路由容器通过 `app/manage/lib/content-api.ts` 调用内容接口，上传预处理通过 `content-upload.ts`。列表页共用固定表头与滚动结果区，每次请求 30 条。服务端先按团队、状态和适用的搜索条件筛选，再分页。滚动接近底部时自动继续；续页失败保留已有结果并允许重试。

展示组件位于 `app/manage/content/`，接收数据与操作回调；数据请求、导航和操作编排由 `app/manage/workbench/`、合集和素材详情路由组件负责。

团队级入口使用 `teamCanWrite()`；具体资源操作读取服务端 DTO 的 capabilities，例如 `can_maintain`、`can_edit`、`can_archive`。只读原因应明确展示。服务端仍重新验证每次请求，隐藏按钮不构成授权。

超级管理员在内容卡片或详情中可使用“复制到团队”，选择目标团队和副本名称；复制单个投放时还需选择目标地图。场景会带上引用素材，活动会带上点位及图片，地图会带上投放、标签、活动及其依赖。同次复制中的重复引用复用一个副本，复制后的编辑互相独立。活动参与记录不复制，新活动地图关联默认为暂停。归档内容及归档依赖需先恢复；失败时不会留下部分副本。

## 团队与资源上下文

- 基础素材类型以 URL 的 `type` 为准；场景通过独立路由区分。
- 页头切换团队时改写 `organizationId` 并移除 `workspaceId`，不自动进入第一个合集。
- 详情页通过 `useResourceTeam()` 对齐资源所属团队和 URL；对齐前显示加载状态。用户主动切换团队时返回新团队对应列表。
- 合集由 URL 指定；现场上传在页面内选择。链接已指定但失效的合集不会被静默替换，用户需重新选择；未指定且团队只有一个合集时可自动选中。
- 合集归档/恢复后重新加载地图与投放能力。
- 素材和场景均使用缩略图网格；搜索和归档筛选保留在页面状态。
- 基础素材详情通过当前列表页的 `assetId` 参数选择，不触发页面导航。右侧浮岛与列表独立滚动，窄屏采用 Sheet；浏览器后退可关闭刚打开的详情，切换素材替换当前选择。详情写入后原位更新已加载的列表，保留筛选与滚动容器。

原 workspace UUID 继续作为合集和二维码标识。地图读写的是 Placement，细节见 [地图交互](map-asset-interaction.md)；场景保存与播放见 [Scene](scene-asset.md)。

## 活动与投放

活动内容页面统一管理名称、参与规则、打卡点图片和固定地点，以及弹幕活动的参与区域。投放只关联目标地图并设置启停状态，不复制或覆盖坐标、规则和打卡点。新关联默认为暂停，仅提供开启、暂停两种状态，开启后小程序才可发现。两种状态都占用唯一地图关联；必须先取消原关联才能关联新地图。

弹幕和店铺打卡共用独立三栏编辑器：顶部提供返回活动库、标题和保存，布局复用地图编辑器；窄屏按地图、设置、右侧面板顺序排列，各面板保留独立滚动。活动归档/恢复和只读、错误、冲突提示位于左侧设置区。

弹幕左栏维护名称、介绍、留言字数上限及参与范围，中栏显示地图，右栏切换地图关联与参与记录。新活动及未显式配置字数上限的活动默认 50 字；已保存的有效上限继续生效，可配置范围仍为 1–500 字。选择整个地图时不设置固定中心；选择限定区域后可点击地图设置中心，并在左栏填写半径或展开经纬度手填。保存后关联地图使用活动中保存的范围。

店铺左栏维护活动名称、介绍、打卡距离和点位列表，中栏显示点位地图，右栏切换打卡点检视器、地图关联与参与记录。在列表或地图选点会打开对应检视器，可编辑名称、介绍、坐标、打卡点图片和奖励图；选点后点击地图设置固定地点，也可展开经纬度手填。左栏可添加点位，检视器可移除未保存点位或归档/恢复已保存点位；顶部保存统一提交活动与点位草稿，无效点位会自动打开检视器供修正。空活动仍显示三栏和添加点位入口；只读与归档活动可查看内容，编辑按权限和状态禁用。保存后关联地图使用活动中保存的地点。

地图编辑器通过顶部导航栏的“活动”按钮打开弹窗；左侧列表仅保留投放与识别目标。弹窗每行显示活动名称、类型、开启/暂停下拉框、编辑与取消关联入口，状态原位保存并保留并发版本检查；失败可重试，冲突时重载。旧草稿迁移为暂停，新关联默认暂停；活动详情和地图弹窗都提供独立的取消关联操作。标题旁的图标在新标签页打开活动库，底部左侧“新建活动”打开与活动库相同的创建表单，仅将标题改为“创建并关联活动”，名称、类型及取消/创建操作保持一致；提交会原子创建活动并以暂停状态关联当前地图，成功后关闭创建表单、刷新地图活动列表并保留底层地图。底部右侧继续选择尚未关联地图的已有活动；只读或归档地图不显示这两个入口。取消关联将当前地图的投放置为 `archived` 并从弹窗移除，不归档活动或删除参与记录；再次关联时按最新并发版本恢复原投放，沿用原 ID 与历史数据。点击地图活动标记会打开弹窗并定位对应行，关闭后保留地图布局、列表页签和普通投放选择。原有 `?tab=activities` 链接直接打开弹窗。修改地点仍通过行内“编辑”进入活动定义；地图中的点击或拖动不会改写活动地点，也不会写入普通内容投放。

活动详情的参与记录按投放筛选并分页显示留言与打卡记录，授权成员可隐藏或恢复展示。切换点位、右侧页签和隐藏/恢复记录保留未保存的活动草稿和地图。地图弹窗的编辑链接与素材使用记录中的活动链接在新标签页打开活动编辑器。活动与投放编辑使用各自的并发版本，冲突时保留输入并由用户重新加载。

识别目标仍是团队 Asset，沿用素材接口、权限、并发锁、上传回执和资源保留规则，不新增实体或迁移数据。普通素材库不显示或创建识别目标。识别目标库的 `assetId` 参数复用素材详情浮岛；旧 `/manage/assets/[id]` 识别目标链接和误入其他库的链接会跳到对应的独立详情。地图只投放已有目标并维护当前地图的挂载关系，参考图和生命周期编辑始终在识别目标库完成。
