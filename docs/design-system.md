# UI 规范体系与实践

本项目的 UI 规范采用分层模型：**Token（词汇）→ 组件（语法）→ 强制（lint/review）**。设计决策的唯一事实源在代码仓库内，规范文档与对应源码保持一致。

## 一、体系分层

### 1. Token 层 —— 什么值存在

| Token | 定义位置 | 说明 |
|---|---|---|
| 颜色 | `app/globals.css`（CSS 变量，明/暗两套） | 语义命名：`background/foreground/primary/secondary/muted/accent/destructive/border` 等，经 `tailwind.config.ts` 映射为 `bg-primary`、`text-muted-foreground` 等类 |
| 字体栈 | `tailwind.config.ts` → `fontFamily.sans` | Geist（拉丁，next/font 加载）→ PingFang SC → Hiragino Sans GB → Microsoft YaHei → Noto Sans SC → 系统兜底。**中文不加载 webfont**，全站唯一字体定义点，任何地方不再单独写 font-family |
| 字号刻度 | `tailwind.config.ts` → `fontSize`（词汇表）+ `components/ui/typography.tsx` 的 `VARIANT_CLASSES`（组合） | 六级：30/24/18/16/14/12px + 营销专用 `display`(36px)/`display-lg`(48px)，全部 rem。**theme 已收窄：刻度外的类（text-xl/4xl…）不存在，写了不生效** |
| 圆角 | `globals.css` 的 `--radius` | 经 config 映射为 `rounded-sm/md/lg` |
| 导航浮岛 | `globals.css` 的 `--navigation-*` 与 `--app-navbar-height` | 全站导航共用圆角、阴影、间距和高度约定 |

核心规则：**只用语义 token，不写死值**。禁止 hex 色、禁止 `text-[..px]` 任意值、禁止绕过语义色直接用 `text-red-600` 这类调色板类（分类标识色的例外见下文）。

### 2. 组件层 —— 合法的组合

- **基础组件**：`components/ui/`（shadcn/Radix），自带刻度内的字号字重，使用时不手写文字样式。禁止直接 import `@radix-ui/*` 原始包。
- **文字组件**：`components/ui/typography.tsx` 的 `<Text>`，Polaris 风格 API（详见下文）。

### 3. 强制层 —— 现状与缺口

- `npm run check` 执行类型检查、lint、离线回归与 build；本地提交和 CI 的接入见 [贡献指南](../CONTRIBUTING.md)。
- **lint error**：`app/`、`components/`、`lib/` 通过 `components/ui/` 使用 Radix；直接导入 `@radix-ui/*` 或 `radix-ui`（含重导出、require 和字面量动态导入）会阻止检查通过。
- **零警告门槛**：任意值字号 `text-[..px]`、刻度外字号（text-xl/4xl/5xl…）及 Text 的 className 携带文字类由 ESLint 检查。`npm run lint` 使用 `--max-warnings 0`，warning 同样阻止提交和 CI。
- **图片预览例外**：固定尺寸缩略图使用 `next/image`；用户素材可能来自外站或本地 Blob，使用 `unoptimized` 保留直接加载。匹配参考图需要未知尺寸下的自然高度和本地 Blob 预览，保留原生 `img`，在组件内注明该单行 lint 豁免；不得把该例外扩展成全局禁用。
- **模型缩略图底色**：服务端生成的模型图片使用固定浅灰 `#F5F6F8` 背景，在明暗主题中保持一致。该颜色属于图片的渲染场景，不读取页面主题 token；页面容器仍使用语义色。

## 二、文字体系（全站最重要的一章）

### 字体栈

拉丁字形走 Geist，中文走系统字体链（见上表）。字体回退是逐字符的，中西混排自动各归其位，zh/en 共用同一个栈。若未来需要品牌中文字体，必须走子集化 + 按需加载，并先修订本节。

### 六级刻度

| variant | 字号 | 用途 |
|---|---|---|
| `headingXl` | 30px / 1.875rem | 页面主标题，每页仅一个 |
| `headingLg` | 24px / 1.5rem | 区块标题 |
| `headingMd` | 18px / 1.125rem | 小节 / 卡片标题 |
| `bodyMd` | 16px / 1rem | 正文，**最小正文字号** |
| `bodySm` | 14px / 0.875rem | 辅助信息，不用于成段正文 |
| `bodyXs` | 12px / 0.75rem | 组件级微文本（badge/时间戳/表格备注），禁止承载完整句子 |

排版规则：标题不加负 letter-spacing（CJK 方块字不收紧字距），标题行高 `leading-snug`，正文 `leading-7`；长文行长由容器限制约 65ch（≈32 汉字），组件本身不限宽。

**Display 档**：`text-display`(36px) / `text-display-lg`(48px) 仅限营销页（首页、hero）的展示性大字，utility 直写、不进入 Text variant；console 路由（/manage、/admin、/super-admin 等）禁用。

### Text 组件 API

```tsx
<Text as="h2" variant="headingLg">区块标题</Text>
<Text as="p" variant="bodyMd" tone="subdued">辅助说明</Text>
<Text as="span" variant="bodySm" truncate className="max-w-64">…</Text>
```

- `as` 必填，语义标签与外观（variant）解耦，h1→h2→h3 不跳级。
- `tone`：`default / subdued / critical / success / warning`，对应语义色 token；不直接写 `text-muted-foreground`。**缺省时继承父级颜色**（可安全用于 primary 按钮、彩色横幅等有色表面），需要明确前景色时显式传 `tone="default"`。
- `fontWeight / alignment / truncate / breakWord` 按需。
- **`className` 只准放布局类**（margin/width/display）；字号、字重、行高、颜色、字距一律走 props。`cn` 走 twMerge，className 能静默覆盖 variant——这是逃生舱不是后门，review 重点盯这条。
- 表单标签用 `components/ui/label.tsx`，链接用 `next/link`，不走 Text。

### 三区边界 —— 哪些文字归谁管

1. **文档流内容**（页面/区块标题、成段正文、长说明）→ 必须用 `<Text>`。判断标准：像"文章的一部分"就用。
2. **组件内嵌文字**（按钮、badge、输入框、菜单项、表格内容）→ 用 ui 组件自带样式，不手写字号、不包 Text。
3. **零散 UI 辅助文字**（字段标签、时间戳、计数）→ 允许直接写 utility，但只准刻度内字号 + 语义色 token。

长文例外：`app/instructions/` 的 MDX 用 `@tailwindcss/typography` 的 `prose` 类排版，不与应用 UI 混用。shadcn 官方文档站的 typography 样式（`text-4xl font-extrabold` 等）**不作为本项目依据**。

## 三、颜色使用规则

- 只用语义 token；`destructive` 只用于不可逆的危险操作且必须配二次确认；同一视图只有一个 `primary` 主操作按钮，其余 `secondary/outline/ghost`。
- `muted-foreground` 白底对比度约 4.7:1，是辅助文字的对比度下限，不得再调浅。
- 状态色：`success`（成功/已完成）、`warning`（警示/需注意）、`destructive`（错误/不可逆），各含 `-foreground` 配对，明暗双套，文字对比度白底 ≥4.5:1。柔和底色用透明度修饰（`bg-success/10`、`border-warning/30`），禁止再写 `text-green-600` 式调色板类。
- **分类标识色豁免**：成员角色徽章（purple/blue/gray/green）、资产类型色（音频 purple、锚点 amber）、清理工具的分类区（orange/blue）、owner 皇冠（yellow/amber）——这些是身份/类别色不是状态色，暂允许调色板类（需带 dark: 变体），未来如引入 categorical token 集再收编。

## 四、i18n 相关的 UI 规则

- 默认 `zh`、fallback `en`；en 文本普遍比 zh 长 50–200%，因此：文本容器不定死宽高；截断必须显式（`truncate` + tooltip），禁止静默溢出；带文案的 UI 须 zh/en 各过一遍再算完成。
- 全部字号 rem，跟随浏览器字号设置缩放。
- 已知限制：`html lang` 首帧恒为 zh，客户端 hydration 后由 i18n-provider 修正（cacheComponents 下 cookie 读取位置的取舍）。

## 五、协作实践

- **人**：新人先阅读本文档和现有组件；设计决策变更由实现与规则在同一 PR 中修订。
- **AI**：AGENTS.md 指向本文档与组件源码；AI 写 UI 前应遵守三区边界与 token 规则，新增例外须先修订规则，不允许静默绕过。
- **验证**：改动共享层（token、ui 组件、Text）属于高杠杆操作——合规不等于视觉无损，改完至少人工检查受影响的应用页面与明暗主题。

## 全站导航浮岛

公共页、认证页、团队工作台和管理后台的顶栏，以及地图、场景和活动编辑器的项目栏，都使用 `NavigationIsland` 的实色表面、12px 圆角和轻阴影，不叠加外边框或玻璃模糊。`navigation-row` 的最小内容高度为 48px，桌面外围间距 12px，低于 640px 为 8px；内容可因保存状态或提示自然增高。页面标题和普通工具条不自动套用浮岛。

普通页面的顶栏在文档流内，高度由 `--app-navbar-height` 推导；页面剩余高度不得写死 56px。地图、场景和活动编辑器隐藏全站顶栏与团队侧栏，由自己的导航占位后让工作区填满剩余视口。地图和活动通过 `EditorHeaderBar` 共用返回、图标、标题、状态与操作区；场景的二维码 portal 仍挂在项目栏容器，错误、冲突与只读提示保留在其中。

地图的活动入口位于项目栏，Dialog 标题旁用带可访问名称的跳转图标打开活动库，地图名称仅作为辅助技术描述。标题与底部操作区固定，中间列表独立滚动；底部左侧提供“新建活动”，右侧保留关联已有活动入口，只读或归档地图不显示这两个入口。桌面活动行按名称、类型、状态下拉框、编辑链接与取消关联按钮排列，窄屏将操作放到信息下方。弹窗内状态只提供开启/暂停，新关联默认暂停；活动详情同样只提供开启/暂停，取消关联使用独立按钮。一个活动最多关联一个地图；已关联时详情页禁用新增关联，地图弹窗只列出尚未关联的活动。状态选择立即保存，保存中禁用控件，失败或冲突在原行反馈并提供重试或重载；取消关联后该行消失，可重新关联。点击地图标记定位并突出对应行。正常列表与关联表单不显示用途说明段落；创建关联只显示必要字段与保存/取消操作。

`ConsoleNavigation` 为团队、管理后台和超级管理后台提供同一侧栏：桌面宽 224px，独立浮岛、44px 导航项；手机在内容上方显示入口并打开带标题的 Sheet。链接仍由各业务层提供，保留权限过滤、团队参数和当前页标记。长团队名与面包屑可截断并提供完整标题，账户和语言操作不被挤出。

### 团队管理工作区

四个资料库统一使用 `LibraryCard` 与 `LIBRARY_GRID`：4:3 缩略图、紧凑的名称与类型/日期信息、12px 网格间距，窄屏仍保留两列。活动卡片使用首个有图片的未归档打卡点作为封面来源；没有图片或为弹幕活动时显示对应类型图标。归档状态沿用资料库的徽标与缩略图弱化样式。

`/manage` 的内容库与素材详情共用一个实色主工作面。桌面侧栏与主工作面从顶栏下方一直对齐到视口底部，沿用导航的 12px 沟槽、圆角与阴影。主工作面使用侧栏以外的全部宽度，侧栏和主区各自滚动。标题、工具栏和结果共用主区内边距，缩略图保持 4:3 并从顶部排列。空状态在结果区垂直居中。窄屏使用抽屉导航，主区补足视口高度，长内容随页面滚动。地图合集、活动、场景和基础素材四个列表共用 `LibraryLayout`，表头仅显示标题、操作和筛选。结果独立滚动，接近底部时自动加载下一页；加载失败可在原处重试。结果向上滚过顶缘时，工具栏底部显示细分隔线和轻阴影，回到顶部时收起。

基础素材卡片默认在列表右侧打开详情浮岛。桌面浮岛宽 320px（1280px 起为 384px），与导航、主工作面对齐，压缩列表宽度；内容单列排列并独立滚动，使用记录与归档区以分隔线分组。选中卡片保持标记，关闭后列表恢复宽度；打开、切换与关闭详情保留列表筛选和滚动位置。低于 1024px 使用同样单列内容的带标题 Sheet，保留页面状态和关闭入口。直接访问素材详情 URL 仍提供完整详情页。

详情浮岛以名称、类型与来源开头，重命名和副本操作紧随身份区。预览及识别图优先于基本信息，创建/更新时间和维护人采用紧凑的键值行。识别图使用两列完整图片预览，不再重复显示首图缩略图；图片要求与归档说明通过各自标题旁的问号 tooltip 按需查看，支持悬停、键盘焦点和触屏点击；添加与删除保留原有权限和数量限制。识别图复用 `AssetImagePreview` 的缩略图模式，鼠标或键盘均可打开全屏；全屏沿用 PhotoSlider，并在共享 Dialog 内处理焦点与关闭，Escape 只关闭当前预览，返回原图片按钮。

### 地图投放检视器

地图右栏按当前任务在详情与新增间切换，固定头部身份和底部操作，只有正文滚动。来源内容使用紧凑摘要与按需预览，来源链接打开新标签页；名称、状态、地图位置常显，识别目标、显示设置和标签使用无嵌套卡片的折叠分组，标题保留当前值摘要，校验错误展开对应分组。新增内容在有标题的 Dialog 中选择/准备，返回地图后确认位置与提交，不在窄栏嵌入整个素材库。桌面列表默认272–320px，检视器默认320–384px；两条8px沟槽使用与场景编辑器一致的竖向三点拖柄，分别调整左右栏，地图填满余下宽度。列表可调240–480px、检视器320–480px，并始终为地图保留至少320px；缩窄窗口自动限制实际尺寸，恢复宽屏后回到本次页面中选择的宽度。方向键调整，Home/End到最小/最大宽度，双击或Enter恢复默认；点击不折叠面板。首屏占位和内容共用CSS默认几何，拖拽不重挂载地图。996px以下隐藏拖柄，列表/检视器按需覆盖地图，手机检视器停靠底部；面板切换不改变地图尺寸，地图选点时可收起面板。

地图沿用场景编辑器的高密度尺度：8px工作区沟槽、40px项目栏、28px桌面控件、12px界面标签与列表名称、14px面板标题，正文错误说明保留14px。面板内边距8–10px，字段组间距8–12px；粗指针和手机控件增至32px，手机输入文字保留16px。详情与新增复用单行 `PlacementActionBar`，状态在左、放弃与提交在右，桌面高度41px、手机45px；长状态截断并保留完整title与辅助技术文本，按钮不换行。列表和选中内容卡片使用48px缩略图，模型/视频优先读取已存thumbnail资源；场景使用其引用素材的已存缩略图，无图时保留场景图标，不把模型或视频文件当图片加载。

投放详情顶部合并身份与来源：40px缩略图、14px对象名称、12px类型及不同的来源名称，只保留一份主要标题；素材缩略图本身是预览入口，来源跳转、更多与关闭靠右。下方先排列名称/状态，再用细分隔线划出常驻地图位置；高级设置的标题和当前值摘要同排，避免每项双行堆叠。大预览仍按需打开，字段区不放大图。

位置区的经度、纬度和高度输入常驻；标题同行固定“地图选点”，不折叠、不替换成摘要、不随状态改按钮名称。取点通过地图内的浮条确认或取消；浮条从开始取点就保留固定的坐标/高度区域和两个按钮，只更新文字与确认按钮的可用状态。地图点击只更新候选点，不展开侧栏，不修改输入或直接写入数据；确认才将三个数值写回原输入框，取消保留原值。桌面字段与按钮、地图及底部保存栏在整个过程中保持位置和尺寸；窄屏取点时暂收起覆盖地图的侧栏，确认/取消后恢复原滚动位置，地图尺寸不变；主动打开窄屏列表或详情面板则取消当前取点。切换投放、任务或合集即退出取点，候选点不跨对象复用；只读输入和选点按钮均禁用。

地图取点浮条固定44px高：左侧两行12px坐标/高度，右侧同排“取消 / 确认位置”，状态区与操作区不再上下堆叠。等待选点和已有候选点均占相同高度；窄屏保持横向排列，坐标截断时保留完整title。

投放内容选择器默认混排素材与场景，搜索框旁以类别下拉框筛选，场景作为一种类别；搜索对两者都有效。弹窗使用受视口约束的稳定高度，头部和模式切换固定，搜索与类别工具栏固定在结果区上方。模式使用透明背景的下划线页签，搜索栏与页签分行，面板内保留焦点环的完整空间。加载、空结果、类别切换及上传类型切换只改变中间正文；在已有内容与上传之间切换时保留搜索词和类别。关闭仅使用右上角按钮，不设置底部操作栏；已有内容点击即选中，上传确认按钮放在上传表单内。选择后，新增面板复用弹窗的 `PlacementContentCard`，显示相同的缩略图、名称与类别，卡片尾部标注“更换”，整张卡片打开选择器，不再将名称和更换按钮分开堆叠。选择器、来源摘要和预览只显示必要的名称、类型与操作，省去“随素材更新”“跟随场景保存的最新内容”等机制说明；字段校验和提交状态仍在对应操作附近反馈。

### 活动编辑器

活动库卡片、地图活动弹窗的编辑链接及素材使用记录中的活动链接均在新标签页打开独立编辑器。活动库右上角的“创建活动”打开仅填写名称与类型的弹窗；创建成功后关闭弹窗并刷新活动库，成功提示提供编辑入口。地图活动弹窗的“新建活动”复用同一创建表单，仅将标题改为“创建并关联活动”，名称、类型及取消/创建操作保持一致；成功后刷新地图活动列表，新关联默认为暂停，并保留底层地图。弹幕和店铺打卡共用独立项目栏，返回、标题与保存位于顶栏，活动归档/恢复操作和只读、错误、冲突提示保留在设置区。

两类活动编辑器复用地图的 `ManageGridLayout`。弹幕左栏编辑名称、规则与范围参数，中栏显示参与区域地图，右栏切换地图关联和参与记录。店铺左栏维护活动设置、打卡距离和点位列表，中栏显示点位地图，右栏切换打卡点检视器、地图关联和参与记录；在列表或地图选点会打开对应检视器，点位名称、介绍、坐标、图片和奖励图在此编辑，已保存点位可归档/恢复，未保存点位可移除。

面板沿用实色背景、语义边框与现有圆角；设置和右侧内容各自滚动。响应式几何与地图共用同一 CSS：宽屏三栏并排，中等宽度地图在上、两侧面板在下，手机依次排列地图、设置和右侧面板，外层可纵向滚动，面板仍独立滚动。切换点位、右侧页签及隐藏/恢复参与记录保留未保存的活动草稿和地图。空店铺活动保留三栏与添加点位入口；只读和归档活动保留布局与内容，编辑控件按能力禁用，活动恢复仍受权限控制。

## 第三方场景编排界面

Three.js Editor 的嵌入视口、相机操作、坐标轴与变换工具栏属于第三方边界；保留上游交互，外层限定布局与资源路径。应用直接在同一 DOM 中呈现项目栏、素材库、所选对象检视器和多媒体时间轴，遵守本设计系统及 zh/en 规范。属性、关键帧和撤销由应用管理，按钮不重复实现原生视口的变换工具。

2026-10-22 起，场景工作台固定使用 Light 主题。`app/globals.css` 的 `:root` 与 `.scene-workspace-theme` 共用全站浅色语义 token；`scene-workspace-theme.css` 设置 `color-scheme: light`、6px 圆角，并局部覆盖 `muted-foreground: hsl(0 0% 42%)` 与 `destructive: hsl(0 62.8% 30.6%)`：辅助文字在选中浅灰背景上满足 AA 对比度，错误文字在浅底上保持可读。项目栏、素材库、检视器、时间轴和浮层共用此主题；后台其他页面的主题偏好保持独立。Three 视口通过 `viewport/theme: light` 保留上游浅色背景，工具图标保留原色；应用提供统一的 1 米网格、带米制刻度的原点轴及虚拟摄像机辅助器，轴色沿用 Three 的方向约定。时间轴播放头使用深色 `primary`，结束区域使用 `muted-foreground` 的浅灰透明遮罩。

浮层通过 PopoverContent 的 `portalContainer` 挂到触发器所在的工作台容器，并继承 Light 主题；适用场景的二维码在视口点击、Escape 和卸载时关闭并清理监听。2026-10-29 起，场景工作台采用局部浮岛布局：项目栏在上，素材库独立占满左列高度；舞台和时间轴纵向排列在右列，时间轴只占右下区域。原生工具在舞台顶部，所选对象检视器浮在舞台右侧。项目栏使用全站导航浮岛规则；其他工作面使用实色背景、10px 圆角与轻阴影，工具岛为 8px，控件继续使用现有 6px 圆角与语义 token。窄屏默认收起素材库，整高素材库与舞台检视器交替显示，时间轴保留独立滚动。素材库与时间轴使用三点拖柄调整尺寸，缩小到阈值后自动收起；素材库收起后隐藏拖柄，由项目栏开关恢复，时间轴收起后保留播放工具栏。工作台文字默认不可选，输入与可编辑内容保留文本选择。模型、图片、音频、视频及场景文字共用轨道与出入场编辑；文字与当前场景保存，独立于团队素材库。页面行为与网页/小程序预览边界见 `app/manage/scenes/DESIGN.md`。

场景编辑器的精简规则：同一操作只保留当前布局需要的入口，说明文字优先移入工具提示；不移除保存状态、错误恢复或可访问名称。素材类型决定关键帧参数：可见对象显示不透明度，音视频显示音量，音频不提供无实际视觉效果的旋转/缩放/不透明度控制。参数值与菱形关键帧按钮在同一行，空间音频配置按启用状态逐步展开。相机预览沿用主时间轴播放，不另设重复播放工具栏。

识别目标库位于团队导航的活动和场景之间，复用素材库网格、过滤工具、详情浮岛和窄屏 Sheet。目标类型固定，不显示类型下拉框；新建以识别图和名称为输入。识别图管理独立于地图，地图只展示紧凑的来源摘要与外部编辑入口，挂载关系保留在当前地图中。
