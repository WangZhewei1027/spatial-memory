# Scene renderer

`renderScene` loads a frozen scene snapshot in local Chromium, uses the Web editor's `EditorModels`, surfaces, model pivot and shared Scene Core, then writes PNGs and `render.json`. The manifest records the document hash, downloaded resource hashes, sample time, camera, bounds, screen projections, media source times and renderer statistics. Files stay in the requested output directory; an agent must open the returned images with its image-reading tool.

`probeAsset` renders a single resource and returns geometry bounds, available animation clips, media duration/dimensions and preview files. GLB dimensions have unknown physical units until the author supplies a scale. AABBs and projection rectangles are observations, not collision or occlusion proofs.

From this Web checkout, install package dependencies with `npm ci --prefix packages/scene-renderer`, then build with `npm run build --prefix packages/scene-renderer`. Run `npm pack` inside the package directory to distribute it. Published artifacts contain the bundled browser runtime and Draco decoder, and require Node 22 and Chromium/Chrome. Install a Playwright browser with `npx playwright install chromium`, or set `SPATIAL_MEMORY_CHROMIUM_PATH`. Browser execution and resource-download timeouts are configurable. Failed decoding or missing target frames fails the render instead of producing a successful placeholder. `npm run test:scene-renderer` from the Web root runs browser integration tests; its video fixture also requires ffmpeg.

The localhost server only exposes files registered for the current snapshot. Downloads use no Web session cookies. Models must embed their buffers/textures; external URI dependencies fail with `MISSING_DEPENDENCIES`, regardless of the file extension. Browser requests outside the frozen snapshot are blocked. The scene stays paused; images, textures, model geometry and target media frames must be ready before capture. Rendering is deterministic within the recorded browser/font/runtime environment, not a pixel-equality promise across machines or a substitute for AR device testing.

Camera presets: `audience`/`map` use `(0,1.4,2)` looking along `-Z`; `qr` uses `(0,0,2)`. `front`, `top`, `side` fit the sampled scene. Custom views accept `position`, `target`, `up`, `fov`, `near`, `far` and `fit`. Camera configuration changes the observation only, not the saved scene.

Automatic fitting uses the visible geometry's corners, perspective depth and image aspect ratio. Fully transparent nodes and audio markers do not affect it. Invalid or degenerate camera settings fail explicitly. `projection` is a world-AABB projection clipped to camera near/far planes, but not to the image edges; inspect `projectionStatus` (`projected`, `depth-clipped`, `outside-depth-range`, `empty`, `non-finite`, `audio-marker`) before using it. `inFrustum` means intersection, not full containment. Audio nodes report `audioMarker:true`, null geometry bounds and zero triangles while retaining real media metadata.
