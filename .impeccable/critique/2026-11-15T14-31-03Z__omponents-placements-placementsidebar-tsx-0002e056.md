# 地图合集 Editor 右侧栏 UI 审计

日期：2026-11-15（Asia/Shanghai）

Method: dual-agent (A: /root/layout_review · B: /root/ui_evidence)

范围：`app/manage/components/placements/PlacementSidebar.tsx` 及详情、新增、来源选择和共享布局组件。现有页面审计与布局建议，未修改产品源码或业务数据。模式：Operate。

## 结论

推荐保留“投放列表—地图—检视器”三栏，将右侧栏改为一次承载一个任务。选择投放时显示详情；点击常驻的“新增投放”入口时切换为新增；素材/场景选择和上传放入独立内容选择器，完成选择后回到地图确定位置。详情中的大预览按需打开，身份栏和保存栏固定，只有正文滚动。

## 设计特异性与总体判断

列表与地图联动、识别目标、来源引用都具有产品特征；右侧栏却把来源详情、空间属性和新增流程顺序堆叠，弱化了地图编辑器的当前对象与当前任务。主要问题是默认呈现的信息和任务过多，减少间距不足以解决。

浏览器实测：中文、浅色、桌面。Assessment B 视口 1512×749 CSS px，右栏宽363px、可视高度665px。Assessment A 另一次桌面观察报告约1512×805；不同捕获条件不用于混算尺寸。

## 优先问题

### P1：两个完整任务共用一个滚动栏

`PlacementSidebar.tsx:26` 的滚动区同时容纳点选提示、详情和新增；第55行在可编辑合集始终追加 `PlacementCreatePanel`。图片详情时“新增投放”标题位于 y=1467，远离首屏。用户需要穿过另一个任务才能执行当前目标。

建议：模式互斥，常驻“新增投放”入口。地图选点信息归属当前任务的位置区；取消新增回到之前的选择并保留会话草稿。

### P1：来源预览抢占编辑首屏

`PlacementEditor.tsx:86` 先渲染来源，再渲染投放设置；`PlacementSourceSection.tsx:70` 默认包括大预览。图片预览实测287×256px，名称字段位于y=875，首屏看不到任何可编辑投放字段。场景没有相同大预览，字段位置因类型大幅变化。

建议：紧凑来源行显示缩略图、名称、类型、“预览/打开来源”；大图、视频、模型预览按需弹出。名称、状态、位置置于主要正文首屏。保留来源内容为实时引用的说明。

### P1：身份和保存操作随正文滚走

`PlacementEditor.tsx:47` 的身份栏、`:75` 的保存按钮均为普通流。图片详情滚动749px后，编辑字段可见，保存按钮位于y=-498。Assessment A还实测从侧栏底部切换对象后保留原滚动位置，新对象身份不可见。

建议：固定对象名/状态/未保存标记，固定底部“放弃修改、保存投放”；正文独立滚动。切换对象时保证新对象身份可见，正文重置或按对象恢复滚动，不继承无关对象的滚动位置。

### P2：新增嵌套素材库，坐标空间不足

`SourcePicker.tsx:80` 的素材列表高240px，实际滚动内容1619px，嵌套在外侧右栏滚动区内。上传入口同时展示8种类型。详情栏363px经过内边距与缩进后字段可用宽度289px，`PlacementLocationFields.tsx:37` 的三列坐标输入各91px，长小数被裁切。

建议：用宽一些的内容选择器承载“已有素材/场景/上传”。选完收束为摘要＋更换；回到地图确认位置。经纬度两列，高度另行；精确数值可以按需展开，但当前位置摘要和选点操作常显。桌面右栏设置可编辑宽度下限，窄窗口优先收起列表，而非继续挤窄字段。

### P2：切换任务需要草稿保护（源码风险）

`PlacementSidebar.tsx:48` 以placement.id重挂载详情；`usePlacementForm.ts:108` 将草稿保存在组件状态；关闭在 `PlacementEditor.tsx:54` 直接清空选择。代码路径未见跨对象草稿保存或切换确认。该项没有通过实际修改表单复现，不当作运行时已证实缺陷。

建议：布局重构时明确会话草稿策略。切换详情、新增、内容选择器不应隐式丢弃编辑；关闭有修改的对象时保留草稿，或给出保存/放弃/留在当前。维持服务端能力检查、乐观锁、失败恢复与明确应用坐标的契约。

## 推荐布局

| 区域 | 详情 | 新增 |
| --- | --- | --- |
| 固定头部 | 对象名、状态、关闭、更多操作 | 新增投放、取消 |
| 首段 | 紧凑来源摘要；名称、状态 | 已选来源摘要＋更换；可选投放名 |
| 核心 | 当前位置、地图重新选点；精确坐标展开 | 明确在地图选点，必要时手动输入坐标 |
| 次要 | 识别、显示、标签分组按需展开 | 创建后的详细属性在详情中调整 |
| 固定底部 | 未保存提示、放弃修改、保存投放 | 缺少内容/位置的提示、创建并投放 |

已经配置的识别目标、显示参数或标签应在折叠标题中显示摘要，不能完全隐藏。精确坐标使用当前产品坐标系；地图点击仍只产生候选位置，经明确确认才应用到草稿。来源编辑会影响其他投放的现有语义保留。

已有内容或上传只占据内容选择阶段，选完立即回到地图。上传仍遵循当前允许类型、上传阶段反馈、失败重试和原子创建协议；不能为节省步骤而静默创建多余素材。新增成功默认进入新投放详情；若高频连续投放，可提供保留来源的“继续新增”。

响应式方向：宽桌面保持三栏；右侧检视器建议约340–380px，左侧列表可更紧凑。中等宽度收起左列表到抽屉，确保地图和检视器可同时使用。手机采用地图＋按需打开的编辑面板，定位阶段让地图可操作。这些是设计建议，未做本次移动端实测。

## 方案对比

| 方案 | 收益 | 代价与判断 |
| --- | --- | --- |
| 默认折叠新增与来源预览、固定保存栏 | 改动较小，能快速减轻滚动 | 两个任务仍在同一条内容流；适合过渡 |
| 单任务右栏＋独立内容选择器 | 明确当前对象；内容选择更宽；地图定位不中断 | 涉及模式与草稿管理；推荐 |
| 右栏拆为多个属性页签 | 适合未来参数大幅增加 | 当前常用字段较少，容易把位置、识别等相关信息拆散；暂不优先 |

## 认知负荷与用户风险

单一任务焦点、顺序决策、工作记忆、渐进披露四项薄弱，判断为高负荷。上传8个类型是决策密度信号，不能将“超过四个选项”单独当作缺陷定论。

- 高频管理员：跨投放修改时重复找字段和保存；旧滚动位置削弱对象辨认。
- 新用户：地图候选点、详情坐标、新增坐标同时出现，难以判断点选作用于何处。
- 键盘与辅助技术用户：长线性表单与嵌套来源列表提高导航成本；本次未跑完整键盘验收。

情绪路径：选择对象时反馈直接；来源预览与长表单增加搜寻成本；滚到底部出现新增流程而非当前任务保存，削弱完成感。
